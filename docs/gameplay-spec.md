## 2. 核心规则（设计建议）
- 回合：我方先手；我方1个**有效**动作 → 敌方1个动作 = 1回合。4个动作有效执行时都消耗本回合。
- **无效动作不耗回合**：内力不足时剑技、药库存0或生命已满时用药，按钮置灰/提示，不扣资源、不推进回合。
- **击杀即结算**：我方动作使敌生命≤0时立即胜利，敌方本回合不行动；我方生命≤0立即失败。
- 伤害 = max(1, round(攻击 × 倍率 − 防御))；**守势减伤在此之后再 ×0.5 并向下取整**（31→15）。首段不加随机/暴击。
- 守势：只作用于本回合敌方那一次行动，回合结束即失效，**不可叠加**（连续守势每次独立生效，不累积）。
- 治疗：回复后生命封顶为生命上限（100），溢出作废。
- 内力：每场战斗开场重置为20；上限30，不溢出。
- 失败：可再战，建议回到进场前快照（含药品数，战斗中用掉的药返还）；失败不发任何胜利奖励。

## 3. 可调数值表（设计值，非实测）
| 参数 | 设计值 | 理由 |
|---|---|---|
| 男主 生命 / 攻击 / 防御 | 100 / 12 / 4 | 整数好算，普攻10 |
| 内力 上限 / 开场 | 30 / 20 | 开场可连放2次剑技 |
| 普攻 | 倍率1.0 → 10伤，**+5内力** | 攒内力手段，不是废招 |
| 剑技 | 倍率1.8 → round(21.6−2)=20伤，耗10内力 | ≈2倍普攻；内力不够无法连放 |
| 守势 | 本回合受伤×0.5（向下取整），**+8内力** | 吃半伤并回多数剑技成本 |
| 回复药 | 回35（封顶100），初始2瓶 | 有限库存防拖延 |
| 敌：厉横 生命/攻/防 | 100 / 14 / 2 | 约7~8回合结束 |
| 敌行动循环 | 普攻→普攻→蓄力(无伤)→重击，循环 | 固定节奏，可读可学 |
| 敌普攻 / 重击 | 1.0=10伤 / 2.5=31伤（守势下15） | 重击是"守还是抢"的取舍点 |

防滥用检查（纸面）：
- 守势有价值：守重击少吃16血（31→15），并比普攻多回3内力（+8 vs +5）；代价是少打10伤。守势+8不足一次剑技的10，需再配一次普攻（或开场剩余内力）才能放剑技。
- 药品不能无限拖：敌4回合循环共出伤10+10+0+31=51（均约12.75/回合），一瓶药35≈不到3回合伤害，且库存仅2瓶、用药回合不输出。
- 剑技不能全程压普攻：开场20内力只够2发；之后每发剑技需2次普攻（+10）或守势+普攻（+13），持续输出必然普攻/剑技交替。

## 4. 四动作决策（提示文案方向）
| 动作 | 何时用 | 代价 |
|---|---|---|
| 普攻 | 内力<10，或敌普攻回合 | 伤害低 |
| 剑技 | 内力≥10；尤其能在重击前把敌打死时 | 耗内力 |
| 守势 | 敌蓄力后的下一回合（重击回合） | 本回合不输出 |
| 回复药 | 看**即将到来的伤害**：若下次敌行动的伤害（普攻10/重击31）会把你打到很低或致死就喝；**避免在重击回合喝药**（喝完立刻吃31，净回仅4），重击回合优先守势，药放在蓄力回合或普攻回合喝 | 用掉回合和稀缺库存 |

## 5. 敌方强招预告（建议，需与现有能力核对）
- 首选：把"蓄力"做成敌方一个无伤行动，战斗日志/飘字显示"厉横握紧刀柄，正在蓄力！"。
- 若不支持独立无伤行动，替代（不扩系统）：固定第4、8、12…回合重击，并在战前由NPC现有对话提示"他每出三刀就要砍一记重的"（台词需剧情侧同意）；或仅在敌名旁显示文字状态。

## 8. 简短成长目标（首段内，不引经验/等级）
- 首战：学会四动作（读蓄力→守势、攒内力→剑技、按来伤判断用药）。不另设首战数值奖励。
- 交付委托后：一次性攻击+2（12→14，普攻12、剑技round(25.2−2)=23）与回复药+1，仅发一次。
- 注意：交付在本段唯一战斗之后，攻击+2在首段内无战斗可用，"可感"主要靠结算面板展示前后数值，真正体感在后续内容。

## 9. 轻量验证清单
1. 每个有效动作后回合推进一次、敌行动一次；击杀回合敌不行动。
2. 无效动作（内力不足/药0/满血用药）不扣资源、不推进回合。
3. 伤害与表一致：普攻10、剑技20、敌普攻10、重击31、守势下15；守势次回合失效。
4. 治疗封顶100；内力封顶30，开场为20。
5. 敌循环与预告出现在第3、7…回合（蓄力）、第4、8…回合（重击）。
6. 失败→再战回到进场前快照，无胜利奖励；新手3次内可赢（找1~2人试）。
7. 交付奖励一次性，存档/重启后不重复（对应 test-plan.md #9、qa-checklist.md"完整主线与奖励"项，仅为对应关系，不代表已一致或已通过）。

## 10. 实现依赖（需开发确认，非事实）
1. 数值能否集中配置（常量/配置表）。
2. 是否支持敌方固定行动序列与"蓄力"无伤行动；日志/飘字能否显示预告。
3. 守势减伤+回内力、普攻回内力、向下取整规则是否已有或需小改。
4. 无效动作置灰且不耗回合；击杀立即结算。
5. 失败再战的快照范围（是否含药品）与存档时机。
6. ui-spec.md 指令环含"逃跑"，首段建议隐藏或置灰（需与UI侧对齐）。
