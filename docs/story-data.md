1. 接取原周伯委托后，村口再与周伯交谈接支线。
   周伯：“竹林里有位背剑姑娘，遇见了替我问声平安。”
   沈砚：“您交代的事，我一起留心。”
2. 竹林现有交互点与少女对话。
   林照晚：“我在寻药包，不是在等人搭救。”
   沈砚：“那便各做各的，遇事互相照应。”

3. 回村口原交互点与僧人对话。
   明澄：“沈砚，你下山也不叫我？”
   沈砚：“好兄弟，来得正好。这位是林照晚。”
   林照晚：“一个急着赶路，一个还肯等人，倒也相配。”
4. 原厉横战斗、周伯交付照常完成；村口再与周伯交谈收束。
   周伯：“事情办妥了，路上也有伴了。”
   明澄：“一路同行，饭钱各付。”
   林照晚：“先说好，不许替我拔剑。”
   沈砚：“好，山河路远，我们一起走。”
药包仅作台词背景，不产生寻找或拾取任务。“同行”仅结尾叙事。

## 状态与事件
建议新增唯一命名空间 `storyExtras.bambooCompanions`，不改原任务。使用单一状态枚举。

| 当前状态 | 事件及守卫 | 下一状态 |
|---|---|---|
| locked | 权威读取：原委托已接、未交付 | available |
| available | 村口周伯新交互完整结束；再次确认原委托已接未交付 | accepted |
| accepted | 竹林少女新交互完整结束 | girlMet |
| girlMet | 村口僧人新交互完整结束 | bothMet |
| bothMet | 权威读取：原委托确已成功交付 | ready |
| ready | 村口周伯新交互完整结束；重验真实交付与回执 | completed |
| completed | 任意重复事件 | 不变，可重播结尾，不再授奖或弹获奖提示 |
| legacyClosed | 任意事件 | 不变，仅显示旧事已结，无补奖 |

补全规则（优先校验数据合法性，再归并，再处理当前交互）：
- 未接支线的 locked/available 若发现主线已交付，转 legacyClosed，不假造参与经历。已接支线可在主线交付后继续补少女、僧人对话。
- 每次载入、主线变化与对话结束均归并 `bothMet + 已交付 → ready`，不依赖错过便无法重播的历史事件。
- 未列出的事件一律不变。重复事件不跳段；一次交互最多消费其开始时对应的一段对话，不能一次点击连过多段。取消对话不推进。
- 事件拟名：mainStatusObserved、talkZhou、talkGirl、talkMonk。场景、人物、主线有效状态由本地整合层读取验证，不能信任 UI 声称的 delivered=true。胜利不等于交付。
- 主线无法读取/不明：暂停本支线推进与结算，保留数据。若原委托支持取消或重置，则未接时暂停，重新接取后恢复；不擦除已记对话。原系统有效完成记录才是交付依据。

## 一次性奖励与提交
奖励为任务文本“同行之约”和结尾对话解锁，以本块回执记录；**不是**新称号系统、货币、物品或队友能力。不触碰钱包、背包，原任务奖励仍由原流程发放。

仅 ready 可结算：确认原任务真实交付且 rewardReceipt 为 null；将 completed 与回执 bambooCompanions.v1.promise 在同一次一致性保存中提交，成功后才显示获奖提示。失败保留原状态，可重试；读档本身不授奖。若原存档没有一致性保存能力，先解决本小块原子保存，再启用结算。
completed 必须有该回执，其他状态必须为 null。矛盾时保留原始块并停用支线，绝不把异常 completed 回退到可领奖状态。重复结尾交互不再次显示奖励。

## 旧档兼容与未知版本保护
- 缺失本块：按当前真实主线状态初始化。已交付→legacyClosed；已接未交付→available；未接→locked；主线未知则延迟初始化。新档同规则。迁移不发奖励，不按未知历史补对话或奖励。
- 合法 v1：原样保留已记状态与回执，再执行上述归并。不会重置支线进度。
- 未知更高/更低版本、未知状态、类型错误、矛盾回执、损坏块：原样保留整个块，仅停用本支线，不能当成缺失或降级覆盖。本提案无 v0 自动升级规则。
- schemaVersion 仅为本扩展版本，绝不覆盖游戏存档版本。缺失初始化只新增本命名空间；主线、钱包、背包、战斗结果、其他扩展一字不改。若整体存档版本本就不受支持，遵循原加载保护，不强行加载。
