# 第10轮 P0 修复：白袍碎斑 + 脸部错位

日期：2026-11-26　分支：round10/p0-texture-fix

## 结论先放这里

美术评审判定的两项 P0 不是"贴图导出损坏"，**主因是 `toon_char_front.gdshader` 的 gutter 填充逻辑误伤**。
把 shader 参数改掉 + 贴图做 UV 岛边缘扩张，两项一起修。

## 一、贴图长什么样（实测）

`shenyan_hero.glb` 内嵌主贴图 `shenyan_albedo_fixed` 是 **TripoSR 逐三角面烘焙的碎片 atlas**：

| 指标 | 数值 |
|---|---|
| UV 岛数量 | 718 个 |
| 中位岛面积 | 15 px |
| 面积 < 50px 的碎岛 | 571 个（79.5%） |
| UV 覆盖率 | 26.51%（其余 73.5% 是深色碎石噪点背景） |
| 像素重叠 | 10.10%，最多 20 层 |

UV 覆盖率只有四分之一，意味着**四分之三的贴图是空隙**。这些空隙是近黑噪点（亮度 <40 占 40.2%）。

## 二、碎斑是怎么产生的

shader 想用 gutter 把空隙涂成布料色，条件是：

```glsl
bool gutter = lum >= 0.18 && lum < 0.62 && chroma < 0.14
    && !skin && !trim && (uv_edge || lum < 0.56);
```

命中就 `c = fill_color`（沈砚 = 0.86,0.86,0.88 冷灰）并加 `EMISSION = c * 0.85`。

在真贴图上跑这个判定：全图命中 13.6%，**UV 岛内命中 16.6%**。
可视化（红色为命中区）正好是：

- 白袍色块边缘的一圈（`uv_edge` 分支）
- 袍子褶皱暗部（`lum < 0.56` 分支）
- 脸上的一小块

—— 和评审说的「白袍大面积灰黑碎三角斑」「脸部白色横条」完全对得上。

**根子在于：gutter 的本意是"补空隙"，但它的判据是"看颜色猜"，而白袍的褶皱暗部和冷灰空隙长得一样。**

## 三、改了什么

### 1. `shaders/toon_char_front.gdshader`

新增开关，默认 1.0 不影响其它角色：

```glsl
uniform float gutter_enabled : hint_range(0.0, 1.0) = 1.0;
bool gutter = gutter_enabled > 0.5 && ...   // 原条件
```

### 2. `scripts/world/toon_model.gd`

- 新增 `gutter_for(path)`：`shenyan` / `shenyan_hero` → `0.0`，其余 `1.0`
- `make_textured(..., gutter: float = 1.0)` 传递 `set_shader_parameter("gutter_enabled", gutter)`
- `apply(..., gutter: float = 1.0)` 加参数并递归透传
- `_finish_instance` 传 `gutter_for(path)`

关填充的前提是**贴图空隙已经被填满**，否则关掉会露出原来的黑噪点。

### 3. 贴图：UV 岛边缘扩张

对三处物理贴图做了「最近邻背景填充」——把每个空隙像素用最近的岛像素颜色填满（最远距离 60px，全覆盖）：

| 文件 | 原大小 | 处理后 |
|---|---|---|
| `assets/glb/shenyan.glb` | 5.26 MB | 2.48 MB |
| `assets/glb/opt/shenyan.glb` | 2.35 MB | 1.45 MB |
| `assets/glb/opt/shenyan_hero.glb` | 2.29 MB | 1.53 MB |

文件反而变小，是因为去掉了 40% 的高频黑噪点，PNG 压缩率大幅提高。网格、骨骼、动画、材质数量全部未变（各 3 mesh / 5 anim / 1 skin）。

同步更新了 Godot 提取出来的外部贴图（`gltf/embedded_image_handling=1` 会自动提取）：

- `assets/glb/shenyan_shenyan_albedo_fixed.png`
- `assets/glb/opt/shenyan_shenyan_albedo_fixed.png`
- `assets/glb/opt/shenyan_hero_shenyan_albedo_fixed.png`

## 四、怎么验证

本机没有 Godot，只做了结构校验（GLB 合法、buffer 长度自洽、贴图 PNG 头正确、节点数一致）。**必须上服务器跑真渲染**：

```bash
# 1. 重截近景，和 r9/r10 基线对比脸部、袍子
godot --path . -s tools/capture_shenyan_round10.gd

# 2. 转台 4 角度 + 走路 8 帧硬指标
ls captures/kimi_walk_0*.png   # 应有 00~07 共 8 张

# 3. 项目自带验证
bash verify-round10.sh 2>/dev/null || bash qa/run_all.sh
```

验收看三点：

1. 白袍上不再有灰黑碎三角斑（尤其肩、袖、裙摆）
2. 脸部没有白色横条，五官完整
3. 袍子暗部保留自然的褶皱阴影（不是被涂成一片死灰）

**如果关掉填充后出现了新的黑洞**（说明某处空隙没被填到），把 `gutter_for` 里 `shenyan_hero` 改成 `0.5` 折中，或者重新跑填充脚本加大判据范围。

## 五、回滚

原文件都在同目录备份，改回名字即可：

```bash
mv assets/glb/shenyan.glb.bak assets/glb/shenyan.glb          # 若存在
mv assets/glb/opt/shenyan_r9.glb.bak assets/glb/opt/shenyan.glb
mv assets/glb/opt/shenyan_hero_r9.glb.bak assets/glb/opt/shenyan_hero.glb
git checkout shaders/toon_char_front.gdshader scripts/world/toon_model.gd
```

## 六、还没解决的

- 美术评审 P1-3「头发高光过曝块状白斑」：贴图高光区（>200 亮度占 11.3%）没有单独处理，属于烘焙时的高光烧进 albedo，要另做压制
- P1-4「角色冷调 vs 场景暖黄」：这是色调统一问题，可在 `tint_color` 或环境光上做，不在本轮 P0 范围
- 脸部错位若修完 shader 仍有残留，则是 UV 接缝真的穿过五官（需 UV 重排，得用 Blender）
